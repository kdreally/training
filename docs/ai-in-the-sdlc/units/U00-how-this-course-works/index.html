Phase 0 — Orientation

Where you are

This is the first unit. You already write software. What you may not have been given is a clear way to work with a coding agent without feeling that everyone else was born knowing the prompts. This unit explains how the course is built, how to get stuck productively, and how a human will assess your work.

What you will be able to do

  • Describe what a unit contains and what each part is for.
  • Use a stuck protocol instead of pasting a whole ticket into a chat and hoping.
  • Submit work in a shape a trainer can mark fairly.
  • Separate practice from the graded assignment.

What you need already

Nothing from this course. You need to be able to open folders and read technical prose slowly.

Time and energy

About 40–60 minutes. There is no tool to install. Take a break if the meta-talk makes your eyes glaze; the later units depend on these rules.

Why this exists

Courses about AI tooling often start with a product tour. Then the product renames a button and the notes die. This course starts with the rules of the work: what you will write, what "done" means, and what to do when a lesson feels slippery. You are not behind. You were under-briefed.

What a unit is

A unit is one folder about one idea. You are done when you can do what the unit claims, not when you have scrolled to the bottom.

Practice vs assignment

Practice is where a wrong answer is information. The assignment is evidence for a human trainer. The "explain in your own words" prompts exist so a copied paragraph cannot pass as understanding.

How assessment works

  1. You complete the assignment.
  2. You submit the files it names, in a folder named the way it asks.
  3. A human marks against the rubric.
  4. Feedback should point at criteria.

If a task is ambiguous, write the assumption you made and why. A trainer can mark an honest assumption. Silence is harder to mark fairly.

The stuck protocol

When a unit stops making sense, do this before you open a chatbot:

  1. Write the last sentence that made sense.
  2. Quote the first sentence, file, or error that did not.
  3. Re-read the vocabulary table for the words in that spot.
  4. Re-read the worked example once, slowly.
  5. Change one thing in your own notes, then see if the confusion shrinks.
  6. Write what you tried.
  7. Ask your trainer with steps 1–6 attached.

Using an agent to escape a lesson about agents, before you can tell a good answer from a fluent one, tends to deepen the fog. The protocol is the tool for this course.

Pace

Re-reading is allowed. Speed is not the grade. The generations you will review later are often confident and wrong. Learning to slow down is part of the skill.

Worked example

Scenario. You open a later unit and feel lost at the phrase "fence the change."

Useful note:

Last thing that made sense: a prompt asks the agent to do today's task.
First thing that did not: "fence the change" — I do not know what a fence is yet.
Vocabulary: this unit's table does not define fence. The index says U18 does.
I did not skip ahead to invent a meaning.
I wrote: "I think a fence is a limit, and I will wait for U18 to define it."
Question for trainer: none, unless U18 never defines it.

That note is enough. You did not need a generated essay about fences.

Common errors

Skipping to the assignment

What you see: The written answers sound like the headings of the lesson and fall apart on the "why."

What it means: The teaching sections were treated as optional.

What to do: Read why, then the teaching, then the example, then the checkpoints. Then the assignment.

Submitting a chat log with no filenames

What you see: A trainer receives a long paste and cannot tell which paragraph answers which question.

What it means: The submission format is part of the work.

What to do: Use the exact filenames in assignment.md.

Checkpoints

Answer for yourself:

  1. What is the difference between practice and the assignment?
  2. What are the first three steps of the stuck protocol?
  3. Why can you read the rubric before you submit?

Assignment

U00 Assignment — Show that you know the rules of the course

Submit one folder or zip named:

U00-YourName

Files to submit

1. answers.md

Answer in your own words. Short paragraphs are enough.

  1. Unit. In 3–5 sentences, explain what a unit in this course is, and name three parts of a unit and why each exists.
  2. Two kinds of work. Explain the difference between practice and an assignment. Include who the assignment is for.
  3. Stuck. List the seven steps of the stuck protocol in your own wording. One line each is enough. Then write a filled-in example for this situation: you do not yet know what "standing instructions" means, and you are tempted to ask a chatbot for a definition before reading on.
  4. Evidence. Why does this course grade files you write, rather than a live reply from a model? Two or three sentences.

2. checklist.md

Copy this list and mark each item [x] when it is true:

- [ ] I read the U00 README, including "Why this exists."
- [ ] I can say what a rubric is for.
- [ ] I wrote answers.md in my own words.
- [ ] I read the U00 rubric before finishing answers.md.

Definition of done

  • answers.md and checklist.md exist with those names.
  • Question 3 includes both the seven steps and a filled-in example.
  • The checklist is honest.

Partial credit

  • Q1: 3/5 if the definition is right but only one part is justified.
  • Q3 steps: 3/5 if five or six steps are present and the missing ones are not the "write what you tried" step.
  • Q3 example: 1/3 if they ask a chatbot immediately and also mention the protocol.
  • Do not penalize imperfect English. Do penalize a paste of this README with the examples unchanged.

Must-have vs nice-to-have

Failing any must-have row caps the grade at 15/20 and that row is "revise and resubmit." Q4 may be thin without failing the unit.
