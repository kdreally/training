# Course home — AI in the Software Development Life Cycle

Welcome. This course teaches a way to use a **local coding agent** inside a software project: standing rules, specifications, prompts, and the checks that decide whether generated code is good enough to keep.

It does not teach a programming language, and it does not follow one product's branding. You already write code. The new skill is directing the agent so the repository stays coherent.

## How it works

1. Open the next unit folder under `units/`.
2. Read that unit's `README.md` in order. The "why" is part of the lesson, not a preface you skip.
3. Do the practice exercises.
4. Complete the assignment and submit it the way your trainer asked.
5. Read the **rubric** in the unit before you submit, so the scoring is not a surprise.

You do not need to be fast. A messy first prompt is normal. Every unit explains the idea before it asks you to use it.

## Order

Work units in ID order: `U00` → `U29`. Full list: [units/INDEX.md](./units/INDEX.md).

Later units assume earlier ones. The running example is the same small project throughout: [examples/shelf](./examples/shelf/).

## What you need

- A computer with a terminal you already know how to use.
- Git, enough to inspect a diff and restore a file. This course will not reteach Git.
- Node.js 20 or newer, so you can run `npm test` in the shelf example when a unit asks. Check with `node --version`.
- A text editor.
- Optional: a local coding agent you already installed. Graded work never requires it. You can finish every assignment from the lesson text.
