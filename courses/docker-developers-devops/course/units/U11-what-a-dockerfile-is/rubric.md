# U11 Rubric

Visible to learners. Total **20 points**.

| Criterion | Points | Must-have? | Evidence |
|-----------|--------|------------|----------|
| Definition of a Dockerfile is accurate and plainly worded | 3 | Yes | `answers.md` Q1 |
| Names three correct "is not" statements with reasoning | 3 | Yes | `answers.md` Q2 |
| Build context explained as the files Docker receives, not just the Dockerfile | 3 | Yes | `answers.md` Q3 |
| All three parts of `docker build -t ... .` identified correctly | 3 | Yes | `answers.md` Q4 |
| Prediction made before running; real output shown; any difference explained | 4 | Yes | `answers.md` Q5 + evidence |
| Error text present and decoded without fear or hand-waving | 2 | No | `answers.md` Q6 |
| Files named correctly; checklist present | 2 | Yes | folder structure |

### Partial credit notes (assessors)

- Q1: award 2/3 if they describe "a list of instructions" but never mention that Docker reads it (i.e. treat it as a program).
- Q2: award 1/3 for one or two correct "is not" statements; 0 if all are invented.
- Q4: award 2/3 if two of the three parts are right.
- Q5: this is the key task. Award 2/4 if they only show real output with no stated prediction, or a prediction with no run. Award full only when both are present and any mismatch is addressed.
- Q6: award 1/2 if they paste an error but rewrite it in their own words without decoding it.
- Do not penalize imperfect English. Penalize empty answers or pasted lesson text with no personalization.

### Must-have vs nice-to-have

- Must-have failing any single row caps the grade at 15/20 and the unit is "revise and resubmit" for those rows.
- Nice-to-have rows (Q6) can be omitted without failing the unit, but full marks require them.
